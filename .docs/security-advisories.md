# Dependency and image security status

Checked **2026-11-14**.

## Current results

- **Node 24.22.3 is fixed in v3.8.10 through [PR #536](https://github.com/jesposito/Facet/pull/536).** It fixes High HTTP/2 and TLS issues, including remotely reachable TLS server crash CVE-2026-126051. The former v3.8.9 image shipped 24.22.2. [Release run 43135469638](https://github.com/jesposito/Facet/actions/runs/43135469638) passed both architecture builds and the merge job; the lead verified Node 24.22.3 on both published architectures. The host's nvm default is also 24.22.3, and `Facet-95e` is closed. Read `node.md` and `container-base-images.md`.
- **Minimatch 11.0.8 is fixed in v3.8.10.** Upstream commits name GHSA-hqmv-qgp3-jx75 and GHSA-c859-jr93-m5j4, but the public advisory URLs returned 404 and OSV returned no records for 11.0.4, 11.0.7 or 11.0.8. Former affected-range exposure is unverified, but the development-only lockfile now selects the containing fixes. `Facet-0w3` is closed. Read `minimatch.md`.
- **postcss-selector-parser 7.2.1 is fixed in [PR #537](https://github.com/jesposito/Facet/pull/537).** The upstream 7.1.8 changelog names GHSA-67xj-gfww-g738 for crafted-input CPU exhaustion; `main` locks 7.1.7. The public advisory returned 404, so affected-range exposure remains unverified. The update is development-only and the production npm tree is empty. Lint, `svelte-check`, the production build and guarded-dependency tests passed. `Facet-8qm` tracks the update. Read `postcss-selector-parser.md`.
- `npm audit --json` returned **zero vulnerabilities** across 465 dependencies for the locked frontend graph. None of the 65 direct dependency or override `/latest` records inspected was marked deprecated. The audit does not establish that the older local `node_modules` matches the lockfile, and it does not resolve the unpublished minimatch or postcss-selector-parser advisory ranges.
- An OSV package/version query covered **196 unique direct and indirect Go module/version entries** from both module manifests. It matched imaging 1.6.2 and go-jose/v3 3.0.5. Compress 1.20.2 no longer matches its former advisory. Package matching is not reachability analysis and cannot inspect the fixes in Facet's local go-jose replacement.
- GitHub Dependabot reported one open alert: the known imaging TIFF finding. Its lack of a patched upstream version matches the existing mitigation below. The go-jose version matches remain visible to package-based scanners despite Facet's local backports.
- [Security run 43135526868](https://github.com/jesposito/Facet/actions/runs/43135526868) on `795ad77` (`v3.8.10`) passed frontend checks, backend tests, backend `govulncheck` and proxy `govulncheck`. The proxy step also ran the local go-jose replacement's regression tests.
- [PR #533](https://github.com/jesposito/Facet/pull/533), merged as **`25fe89f`** and released in **v3.8.8**, updated Facet to Go 1.27.4 and expanded the local go-jose replacement to cover all three v3 advisories. `Facet-zl8` is closed. The current [published-image scan 43138170223](https://github.com/jesposito/Facet/actions/runs/43138170223) passed on v3.8.10.

## Local patches

- `frontend/vendor/guarded-braces` and `guarded-deepmerge` retain upstream licences and provenance. Remove them only when the consuming dependency chain provides equivalent protection.
- `docker/caddy/third_party/go-jose-v3` is based on v3.0.5 with RSA bounds, CBC-HMAC empty-input and JSON-depth backports, plus an explicit Unicode conversion bound. CI runs `go test ./... github.com/go-jose/go-jose/v3/...` from the parent `docker/caddy` module.
- Facet's default `docker/Caddyfile` uses plain HTTP `:8080` without `acme_server` or `tls internal`. The go-jose code is compiled into Caddy but those PKI paths are not reached by default; custom configurations can enable them.
- `backend/third_party/mailyak-v3` adds SMTP connection/exchange deadlines. It is unrelated to these advisories but is another replacement to review during upgrades.
