# Caddy

Checked **2026-11-16**.

Facet builds **Caddy 2.11.9** from `docker/caddy` with **Go 1.27.4**; both module manifests and the production builder select that toolchain. The Go module proxy reports **2.11.9** as latest. Caddy 2.11.8 and 2.11.9 contain security and bug fixes covering reverse-proxy interim responses, host/path handling, file serving, FastCGI and TLS configuration merging. Facet's exact configuration does not use every affected feature, so applicability must be assessed per fix rather than assumed from the release count.

The proxy graph selects `github.com/klauspost/compress` **1.20.2**, which fixes GHSA-fpmh-frq8-7rj8 / GO-2026-6865. **1.20.4 is latest.** Caddy 2.11.9's own `go.mod` still selects compress 1.20.1, so upgrading Caddy alone did not clear the former finding.

[PR #528](https://github.com/jesposito/Facet/pull/528) was squash-merged as **`fde26de`**, selecting Caddy 2.11.9 and compress 1.20.2 while keeping smallstep/crypto 0.91.0 and the local go-jose replacement. Local proxy tests, vet, `govulncheck`, CGO-disabled build, Caddyfile validation and the go-jose suite passed. `Facet-cyi` is closed, and later releases published both architectures successfully.

The v3.8.11 graph selects OpenTelemetry `otel/sdk` **1.46.0**, `otel/sdk/log` **0.22.0** and `otel/trace` **1.46.0**, all affected by GHSA-q7gw-24fr-5p69 / CVE-2026-128085. Valid U+FFFD runes can bypass attribute-length limits. The default Caddyfile has no tracing directive, so practical reachability is unverified, but the standard modules compile the affected code. [PR #541](https://github.com/jesposito/Facet/pull/541), tracked by `Facet-1ak`, aligns the seven core, log, metric, SDK and trace modules at **1.47.0**. Proxy tests, vet, CGO-disabled build, Caddyfile validation, go-jose tests and reachable `govulncheck` passed in the pinned Go 1.27.4 container. Dependabot PRs #538–#540 cover the three advisories separately.

`go.step.sm/crypto` **0.92.0** is available and requires Go 1.26, which Facet satisfies. It selects go-jose/v4 4.1.9, but Caddy 2.11.9 and smallstep/certificates 0.30.2 still select go-jose/v3. A compatibility build on 2026-11-10 failed with certificates 0.30.2: `jwt.Builder.CompactSerialize` is undefined in `provisioner/aws.go`, and `jose.Expected.Audience` is missing in the Azure and OIDC provisioners. **Keep 0.91.0 plus the local v3 patch until smallstep/certificates supports the 0.92 API; do not take 0.92 as a routine update.**

The local go-jose v3.0.5 replacement covers all three known v3 advisories: RSA bounds (a0111f8), CBC-HMAC empty input (74114c2) and JSON depth (a31af25). [PR #533](https://github.com/jesposito/Facet/pull/533) merged as **`25fe89f`** and was released in **v3.8.8**. OSV still matches the upstream v3.0.5 version; it does not inspect the local backports. The default plain-HTTP Caddyfile does not reach these PKI paths, although the code is compiled in. See `go-jose.md` and `security-advisories.md`.

After changes, run `go test ./... github.com/go-jose/go-jose/v3/...` and `go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...` in `docker/caddy`, then the full security workflow and packaged-image scan.
