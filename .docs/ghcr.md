# GitHub Container Registry publishing

Checked **2026-11-14**.

Push run [42706080159](https://github.com/jesposito/Facet/actions/runs/42706080159) compiled the ARM64 image and then failed the upload with `permission_denied: write_package`. The workflow already had `packages: write`, and the GHCR login step succeeded. In the same run, AMD64 pushed successfully. Other overlapping branch builds also saw intermittent denials, while later non-overlapping publishes succeeded.

The issue was transient and required no configuration change. Release run [43135469638](https://github.com/jesposito/Facet/actions/runs/43135469638) for **v3.8.10** passed both architecture builds and the merge job. The lead verified that the published `v3.8.10` and `latest` manifest serves Node 24.22.3 on both amd64 and arm64. [Published-image scan 43138170223](https://github.com/jesposito/Facet/actions/runs/43138170223) passed. Earlier releases v3.8.4 through v3.8.9 also published both architectures. `Facet-dcy` and `Facet-95e` are closed; reopen `Facet-dcy` if denials recur outside overlapping branch-build bursts. The observed correlation with concurrent publishes is a hypothesis, not a proven registry limitation.

Sources: [failed push run](https://github.com/jesposito/Facet/actions/runs/42706080159), [successful v3.8.10 release run](https://github.com/jesposito/Facet/actions/runs/43135469638), [v3.8.10 published-image scan](https://github.com/jesposito/Facet/actions/runs/43138170223), [GitHub Packages permissions documentation](https://docs.github.com/en/packages/learn-github-packages/configuring-a-packages-access-control-and-visibility), checked 2026-11-14. Direct GHCR inspection from the documentation host was blocked by token authorization; the successful release jobs and the lead's explicit runtime verification are the publication evidence used here.
